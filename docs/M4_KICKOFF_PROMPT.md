hackathon demo, while staying scientifically honest.

## What to build
A single-page, offline dashboard served by one local command, reading only pre-computed artifacts (nothing is
fitted live). Streamlit only as the fallback if the custom page is not working by 13 Oct. No Docker.
Three screens plus an always-visible limits banner ("research prototype; evaluated on a Chinese cohort in
supervised care and a US free-living cohort; estimates, not measurements; not for dosing"):
1. **Clinic list**: patients with days since the sensor, "treatment changed since the sensor (from the record)"
   and the staleness prompt as sortable columns. No default ranking by risk, treatment flag or prompt; three
   states, never blank ("raised (date)", "not raised", "not computed (reason)").
2. **Patient**: last sensor report beside today's shadow with its 80 % band, drawn exactly as Gate 2 scored it
   (never without a band; always labelled "estimated"); the hide-and-reveal switch (the hero interaction: shadow
   first, then the real trace sliding over it); days since the sensor as a fact with no threshold; the report
   since the sensor as sensor-equivalent mean and share of fingersticks above 180, beside the same figures as
   read from the meter; fingersticks shown as read; the staleness prompt only inside its tested range, with the
   plain comparison beside it; a meal what-if labelled simulation; sensor lows read "sensor low, unconfirmed".
3. **Evidence**: every result with its bar, including the misses (Gate 3, record prior) shown as plainly as the
   passes; label check; expiry and case series; band; staleness with both AUROCs side by side; limits; data
   provenance and licences.
Demo patient "Mrs. R." and any genetic-marker field are **synthetic and labelled so on screen**. The record is
FHIR-shaped JSON. Build step: a script that turns `results/` and the reveal traces into one artifact bundle.
Every number on screen must be regenerated by a command in the repo (rule 8).

## Hard rules for this milestone
- No dose recommendations; no low-glucose alarm or low-glucose estimate; no time in range or time below range
  from any estimate; no GMI or estimated HbA1c from fingersticks; the word "alarm" never appears on screen.
- The staleness prompt is "a prompt to consider a new sensor wear", never a finding about glucose, never advice
  on treatment. Gate: profile from 3 or 5 sensor days, at least 4.6 fingersticks a day, first raised by day 11;
  otherwise "not computed" with the reason, as visible as the prompt. Outside the tested range it lives on the
  Evidence screen only.
- Fusion is described as built and measured, never as a gain. Quote only each record's "claim to quote".
- Run `healthcare-reviewer` on all patient-facing copy before it is final, `python-reviewer` on any `src/` code.
- Docs and code change in the same commit; update the roadmap Status table and `docs/PROGRESS.md`.

## Design bar: "absolute stunning, industry grade"
Before writing UI, load the `artifact-design`, `dataviz` and `scientific-visualization` skills and follow them.
Aim at the polish of Linear, Stripe, Apple Health, Oura and Dexcom Clarity combined, for a clinician audience.
- A real design system first: tokens for colour, type scale, spacing, radius, elevation and motion, defined once.
  Light and dark themes, both polished. A restrained clinical palette (one accent, semantic colours reserved for
  meaning, colour-blind safe), tabular numerals for all figures, one serious typeface pairing, an 8-pt grid.
- Hero: a large glucose chart that is the product. Smooth band, crisp trace, annotated meals, a scrubber for
  the reveal, hover crosshair with exact values and units, keyboard accessible. Animate the reveal with purpose
  (200 to 600 ms easing), respect `prefers-reduced-motion`.
- Information hierarchy: one decision per screen, the number that matters biggest, caveats adjacent not buried.
  Honest-uncertainty is the visual signature: bands, "estimated" chips, evidence-grade badges (passed, missed,
  descriptive) that make the misses look deliberate and trustworthy rather than hidden.
- Micro-detail: skeleton and empty states, consistent iconography (SVG), crafted tooltips, sticky header,
  command-palette style patient search, subtle glass and depth used sparingly, no emoji, no stock gradients, no
  lorem ipsum, no layout shift. WCAG AA contrast, focus rings, 16 px gutters at phone width, no horizontal scroll.
- Performance: loads instantly offline, no runtime network calls (fonts and libraries vendored or inlined).
- Verify like a user: run it, drive it with the built-in browser, screenshot at desktop, tablet and phone widths
  in light and dark, fix what looks off, and check the console is clean. Do not report "done" from code alone.
